## 0. Что это одной картинкой

- **Клиент** — новая запись `clients[]` с вечным `id`, как организация. В съёмке лежит
  `clientId`, не имя. Клиент хранит **только своё**: имена, телефоны, мессенджеры, дни
  рождения, годовщину, тумблер «Поздравлять», свои ссылки. Съёмки, даты, гонорары, ссылки
  съёмок — **вычисляются** из съёмок с этим `clientId`, не копируются.
- **Пункт «Клиенты» в настройках** (не в главе «Календарь»). В шапке переключатель
  **«Частные | Компании»**. Внутри «Частных» — **«Все · Пары · Семьи · Персоны»**.
  «Компании» — нынешние «Организации», переехавшие внутрь.
- Клиент **заводится сам** из формы съёмки, **склейка по номеру телефона**. Пара — одна
  карточка на двоих, годовщина — из даты свадьбы (правится).
- **Поздравления** — локальные уведомления раз в год, 10:00 по часам телефона, без сервера.
- **Кнопка мессенджера** в карточке съёмки: Telegram / VK / Instagram / WhatsApp / MAX; нет
  мессенджера — SMS.
- **Контакты iPhone:** клиенты сами сохраняются в телефонную книгу, тумблер вкл/выкл, по умолчанию
  вкл (ответ Алексея 23.10, § 5).
- **Стопка долгов** — вход только нажатием на несданную съёмку в календаре; «сдана» —
  только ручной сменой статуса.
- Хранится **только в нативе** до итерации облака (31); веб не трогаем.

## 2. Модель данных

### 2.1 Клиент (`clients[]`, новый раздел снимка)

| поле (ключ снимка) | что | заметка |
|---|---|---|
| `id` | `"c" + base36(время) + 4 знака` | как `newOrgId` у организаций; вечный |
| `kind` | `couple` / `family` / `person` — «Пара» / «Семья» / «Персона» | ставится по жанру при создании, правится руками (2.3) |
| `people[]` | люди карточки: у персоны один, у пары два, у семьи сколько угодно | 2.2 |
| `main` | номер человека в `people`, «кому пишем» | кнопка мессенджера берёт его способ связи |
| `anniv` | годовщина: день (`ГГГГ-ММ-ДД`) | только у пары; 2.4 |
| `annivManual` | годовщину правили руками | тогда дата свадьбы её больше не двигает |
| `greet` | «Поздравлять» — общий тумблер карточки | 6 |
| `links[]` | свои ссылки клиента (`Attachment` вида `link`) | ссылки съёмок сюда не копируются |
| `telLog[]` | ушедшие номера людей карточки | тот же `TelLogEntry` и `PhoneBook.retire`, что у съёмки и организации |
| `mt` | отметка правки, мс | для облака (31) |

**Человек** (`people[]`): `n` имя и фамилия одной строкой (как `persons[].n`), `tel` телефон,
`bd` день рождения (`ММ-ДД` или `ГГГГ-ММ-ДД` — год необязателен, как в Контактах iPhone),
`msg[]` мессенджеры: `{k: telegram|vk|instagram|whatsapp|max, v: имя пользователя, номер или ссылка}`, `pref` —
какой мессенджер основной.

Чего в клиенте **нет** (решено 23.10): съёмок, дат съёмок, гонораров, ссылок съёмок — всё это
считается: `съёмки клиента = sessions.filter { $0.clientId == id }` (как `OrgBook.shoots`),
суммы — тем же `Money.income`/суммой по валютам, что у организации (`OrgBook.line`).

### 2.2 Связь со съёмкой

- В съёмке новый ключ **`clientId`** (рядом с `orgId`). Одна съёмка — один частный клиент.
- Имя и телефон в съёмке (`contact`, `clientPhone`, `persons[]`) **остаются**: на них держатся
  поиск, список дня, неделя, заметка события в Календаре (30.4). Клиент их не заменяет.
- Съёмка с `orgId` (Компании) частного клиента не получает, кроме случая, когда в ней
  заполнены люди пары (`persons`) — свадьба через агентство: заказчик компания, пара — клиент.
- Корзина: съёмка в корзине из истории клиента выпадает; клиент без съёмок не удаляется сам
  (в нём могут быть дни рождения) — удаляют руками.

### 2.3 Пара / Семья / Персона — как решается

Предложение (из задания): по жанру при создании, дальше правится переключателем в карточке.

| жанр съёмки, из которой клиент завёлся | вид |
|---|---|
| свадьба (`wedding`, двое: невеста, жених), лавстори (`lovestory`) | Пара |
| семья (`family`) | Семья |
| портрет, животные (владелец), праздник (виновник), без жанра («Фотосъёмка») | Персона |
| предметка, реклама, архитектура, репортаж **без** организации | Персона |
| то же **с** организацией | клиента не заводим — это «Компании» |
| пейзаж, стрит (клиента у жанра нет, `GenreSpec.client == false`) | не заводим |

Вид, раз поставленный, следующей съёмкой **не меняется**: портрет невесты после свадьбы не
превращает пару в персону.

### 2.4 Годовщина пары

Берётся из **самой ранней** свадьбы (`genre == .wedding`) среди съёмок клиента; свадьба на два
дня — первый день. Правка руками ставит `annivManual` — дальше съёмки дату не трогают. У лавстори
годовщины нет, пока её не впишут.

### 2.5 Где хранится и как переживает обновления

- Раздел `clients` — **типом** в `Snapshot` (новый `CodingKey`), `clientId` — полем `Session`.
  Тот же файл `light-plan.json`, та же запись `persist()`. Обновление приложения файл не
  трогает (из кода, не мерено на телефоне для нового раздела).
- Файл-копия (`BackupFile.swift`) пишет весь снимок — клиенты в нём будут. **Но** если такую
  копию открыть в вебе и веб её пересохранит — клиенты пропадут (см. § 1). Пока веб заморожен,
  это вопрос только 31.
- Связь «клиент ↔ контакт iPhone» (§ 5) — **не в снимке**: идентификатор контакта у каждого
  телефона свой. Как у зеркала календаря (`CalendarMirrorRecord` в `UserDefaults`), подсказка
  лежит на устройстве, правда — номер телефона.

### 2.6 Встреча с облаком (31)

Клиенты сливаются между устройствами так же, как организации: по `id` + `mt`, удаление кладёт
«тень». Решить в 31: веб либо научится носить раздел `clients`, либо облако хранит его отдельно
от того, что пишет веб. Сейчас ничего под облако не делаем — только `id` и `mt` с первого дня.

## 3. Правила склейки

Ключ номера — `TelFormat.full` (международные цифры: «8 916…» и «+7 916…» — один номер), как у
«Контактов». Номер короче пяти цифр — не номер (`TelFormat.isReal`).

1. **Когда.** При «Сохранить» в форме съёмки (и один раз — проход по всем уже записанным
   съёмкам, § 3.7). Берутся номера `clientPhone` и `persons[].tel`; `orderPhone` — это человек
   заказчика, он к Компаниям.
2. **Тот же номер.** Номер совпал с живым или прежним (`telLog`) номером человека клиента →
   съёмка получает его `clientId`. Пустые поля клиента дозаполняются из съёмки (имя, второй
   человек пары); заполненные **не перезаписываются** молча.
3. **Нет совпадения.** Есть имя или номер → новый клиент, вид по § 2.3.
4. **Два номера одной пары.** Свадьба: невеста A, жених B → одна пара, два человека. Позже
   лавстори только с номером B → та же пара. Если A уже у клиента X, а B у клиента Y (жених
   раньше снимал портрет) — **не склеиваем сами**: съёмка идёт к клиенту по первому человеку,
   в карточке плашка «Номер Ивана есть у клиента „Иван П.“ — объединить?». Объединение — руками.
5. **Номер сменился.** В форме связанной съёмки номер поменяли → номер человека в клиенте
   обновляется, старый уходит в `telLog` клиента (через `PhoneBook.retire`) и продолжает
   узнаваться. Прошлые съёмки свои номера **не переписывают** — это история. Смена номера в
   карточке клиента новые съёмки берут, старые не трогают.
6. **Номер организации и номер человека.** Номера организаций (`phone`, директор, люди с ролью)
   частного клиента **не заводят**. Если номер частного клиента совпал с человеком компании
   (маркетолог заказал семейную) — живут оба, «Контакты» покажут связку. Между «Частными» и
   «Компаниями» склейки нет. Свой номер (`me.phone` и прежние) клиентом не становится.
7. **Без номера.** Клиент заводится (у него может быть день рождения), но **сам не склеивается**
   ни с кем: два «Анна» — разные люди. Форма подсказывает по имени (§ 4.5), привязка — нажатием.
8. **Засев и тестовые данные — одноразовые.** Миграций нет. Первый запуск сборки с клиентами
   один раз проходит по всем съёмкам правилами 1–7 и раскладывает клиентов — это та же функция,
   что при сохранении, а не перенос старого формата. `TestSeed` получает несколько клиентов с
   днями рождения и парой с двумя номерами — для проверок.

```
│ Свадьба · 14 июня                    │
│ Анна и Иван ›          [📞] [✈]      │   ← имя ведёт в клиента, ✈ — основной мессенджер
└──────────────────────────────────────┘
```

**Форма съёмки**: под полем имени — плашка найденного клиента; рядом с полем телефона —
«Из Контактов» (§ 5).
```
│ Клиент   Анна Петрова                │
│          ┌───────────────────────────┐
│          │ ♥ Это Анна и Иван? 3 съёмки│ ← по номеру — привязано сразу;
│          │   [ Да ]  [ Другой ]       │   по одному имени — только подсказка
│          └───────────────────────────┘
│ Телефон  +7 916 …        [ Из Контактов ]
```

## 5. Телефонная книга iPhone (Contacts)

**Читаем** (если разрешено): имя, телефоны, день рождения (`birthday`), даты с меткой
«годовщина» (`dates`), мессенджеры и соцсети (`instantMessageAddresses`, `socialProfiles`).
Поле «Заметки» контакта **не трогаем**: для него нужно особое разрешение Apple
(`com.apple.developer.contacts.notes`), которое выдаётся по заявке (документация Apple
«Accessing the contact store»).

**Разрешение.** Ключ `NSContactsUsageDescription` в `Config/iOS.xcconfig` (как у календаря и
камеры) и строка в `App-iOS/InfoPlist.xcstrings`. Спрашиваем **в момент нужды** (первое
«Из Контактов» с подсказками или первое «Сохранить в Контакты»), не при запуске. С iOS 18 человек
может дать **частичный доступ** — только выбранные контакты; системный выбор контакта
(`CNContactPickerViewController`) работает **вообще без разрешения** и показывает всю книгу.
Отказ ничего не ломает: клиенты живут внутри приложения как раньше (как отказ календарю).

**Бесплатная команда.** Для Contacts, по документации Apple, нужен только ключ описания —
платной «возможности» (capability) в списке нет, в отличие от iCloud/Push/WeatherKit.
**Не мерено**: на бесплатной команде `4A3PUKS9R9` запрос не делался; проверить первой же
сборкой на телефоне.

**Решено (Алексей, 23.10): пишем сами, тумблер, по умолчанию вкл.** Его слова: «Пусть засоряют
книгу, надо просто добавить кнопку вкл/выкл для этой функции, по умолчанию вкл». Были три
варианта (только читать / сохранять по кнопке / сохранять сами); выбран третий с тумблером.

Как это устроено (решения исполнителя, технические; из кода и документации, не мерено):

- **Тумблер** «Сохранять клиентов в Контакты iPhone» — внизу вкладки «Частные», под списком;
  по умолчанию **вкл**. Выключили — новые клиенты в книгу не пишутся, уже записанные остаются.
- **Что пишем.** Каждый человек клиента **с номером** — отдельный контакт: имя и фамилия, телефон,
  день рождения, мессенджеры (профили соцсетей и мессенджеров контакта), у пары — годовщина в
  «Датах» обоих. Человек без номера (ребёнок в семье) в книгу не идёт. «Заметки» не трогаем.
- **Номер уже есть в книге** (ты сам сохранил человека раньше) — нового контакта не заводим и
  твой не правим; оттуда только **читаем** то, чего нет у клиента (день рождения, мессенджер).
- **Правки.** Изменил клиента в приложении — правка уезжает только в контакты, **заведённые
  приложением** (их связь с клиентом хранится на телефоне, не в снимке — как у календаря).
  Из книги обратно в клиента правки не едут. Удаление клиента контакт **не удаляет**.
- **Разрешение** — полный доступ к Контактам (чтобы находить номер в книге и не плодить
  дубли). Спрашиваем при первом открытии «Клиентов», с плашкой «Сохраним в Контакты N клиентов
  (из уже записанных съёмок)» — до вопроса тумблер можно выключить. Отказ или частичный доступ
  iOS 18+ (видна только часть книги, дубли не найти) — тумблер встаёт в «выкл» с подписью почему,
  клиенты живут внутри приложения.
- **«Из Контактов»** в форме и карточке клиента — системный выбор контакта, работает и без
  разрешения: подставляет имя, номер, день рождения, мессенджеры.

## 6. Поздравления

**Когда.** День рождения человека и годовщина пары, **10:00 по часам телефона** (триггер по
календарным полям без пояса — следует за телефоном в поездке; из документации, не мерено).
29 февраля в невисокосный год — 28 февраля. Одно уведомление **на день**, даже если праздников
несколько: «Сегодня: годовщина — Анна и Иван; день рождения — Ольга». Нажатие открывает
карточку клиента (один праздник) или «Клиенты» (несколько).

**Кого.** Клиенты с включённым «Поздравлять». Тумблер — один на карточку (у пары и семьи —
на всех её людей).

**Потолок 64.** iOS держит не больше 64 ожидающих уведомлений на приложение (`StudioSchedule.systemLimit`).
Сегодня `NotificationScheduler.sync` считает чужие запросы занятым местом: два расписания с разными
приставками будут **отнимать место друг у друга** — кто сверился последним, тот и выиграл.
Делим так:

| кто | приставка | мест | почему |
|---|---|---|---|
| студийный час | `lp.studio.` | всё, что осталось (≥ 24) | ближайшие аренды важнее; две ступени на ячейку |
| поздравления | `lp.greet.<ГГГГ-ММ-ДД>` | **не больше 40** | одно на день → 40 ближайших дней с праздниками |
| прогноз переменился | `lp.wx.` | 0 в очереди | говорит сразу, в очереди не стоит (ветка `wt/30-wx`, из кода) |

Поздравления ставятся разовыми запросами на ближайшие дни и переставляются при каждом открытии
приложения (как студийный час). Счёт: 100 клиентов ≈ 100–250 праздников в год ≈ один праздник на
1,5–3 дня; 40 мест покрывают ~2–4 месяца вперёд (оценка, не мерено). Не открывал приложение
дольше — поздравления за пределом не придут; фоновое обновление iOS не гарантировано.

## 7. Мессенджер и стопка долгов

### 7.1 Кнопка мессенджера

В шапке карточки съёмки и в карточке клиента. Значок — основной мессенджер человека «Пишем».

| способ | что открываем | заметка |
|---|---|---|
| Telegram | `https://t.me/<имя>`; только номер — `https://t.me/+<номер>` | второй вид открывает чат, если человек разрешил поиск по номеру — не мерено |
| VK | `https://vk.me/<id или имя>` | |
| Instagram | `https://ig.me/m/<имя>` | |
| WhatsApp | `https://wa.me/<цифры номера>` | работает по одному номеру, имени не нужно |
| MAX | ссылка, которую вписал фотограф (веб-версия), открывается в браузере | слова Алексея 23.10: «его удалили из AppStore, но мы добавим, даже если не будет работать через приложение, можно туда поместить Web ссылку»; вид ссылки профиля MAX — не мерено |
| нет мессенджера | `sms:<номер>` (Сообщения: SMS или iMessage) | слово Алексея: «как обычное смс» |

Ссылки `https://` — универсальные: открывают приложение, если оно стоит, иначе браузер; список
схем в `Info.plist` не нужен (из документации, не мерено). В поле мессенджера можно вставить
ссылку профиля (`vk.com/id123`, `instagram.com/olga`, `t.me/olga`, `wa.me/7916…`) — приложение
вынет имя; ссылка MAX хранится как есть.
Долгое нажатие — меню всех способов: позвонить, SMS, каждый мессенджер.

### 7.2 Стопка долгов на «Съёмках»

**Что долг** (слова Алексея 21.10): съёмка, у которой статус «сдана» не нажат руками. Плюс из
кода: только работа (`kind.isWork`, не встреча и не событие), жанр со сдачей (`GenreSpec.delivery`;
пейзаж и стрит не долг; без жанра — долг), съёмка уже кончилась (ступень сдачи не `ahead`).
Срок сдачи из карточки статус не меняет — просроченная и не просроченная одинаково долг.

**Вход.** Нажатие на несданную съёмку в календаре (день месяца → строка съёмки, неделя,
лента дня) открывает её карточку, и **стопка над ней — все долги**, а не соседи по дню
(`stack(of:)` получает второй режим). Нажатие на сданную или будущую — обычная стопка дня.
Отдельной кнопки «Долги» нет (слово Алексея).

```
┌──────────────────────────────────────┐
│ ▔▔ Портрет · Ольга · 2 окт · −7 дн ▔ │  ← края других долгов, старые ближе
│ ▔▔ Семья · Кузнецовы · 9 окт       ▔ │
│ ┌──────────────────────────────────┐ │
│ │ Свадьба · 20 окт                 │ │
│ │ Анна и Иван ›        [📞] [✈]    │ │  ← мессенджер клиента на каждой карточке
│ │ Сдача: 70 дней осталось          │ │
│ │ [ Отметить «сдана» ]             │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

Отметили «сдана» — карточка остаётся открытой со статусом, из стопки уходит при переходе к
следующей. Связь с клиентом: имя ведёт в карточку клиента, ✈ открывает переписку — то самое
«с одним в VK, с другим в инсте, с третьим в телеге» одним местом.

## 8. План шагов

Каждый шаг — своя ветка, один пуш, тесты, сборка «LP <шаг>» на телефон. Размер грубый:
малый ≈ 1 сессия, средний ≈ 2, большой ≈ 3+.

| шаг | что | зависит | размер | на телефоне видно |
|---|---|---|---|---|
| К1 | Модель клиента, `clientId`, склейка при сохранении и разовый проход по съёмкам; «Клиенты» в настройках: «Частные» (фильтры) и «Компании» (организации переехали); засев | 30б слит | средний | открыть «Клиенты» — твои клиенты собраны из съёмок, пары с двумя людьми |
| К2 | Карточка клиента: люди, вид, телефоны, ссылки, съёмки и суммы (вычисляются), объединить, удалить | К1 | средний | правка имени, «объединить» два дубля |
| К3 | Входы из съёмки: имя в шапке карточки → клиент; плашка клиента в форме, подсказка по имени | К2 | малый | новая съёмка с номером старого клиента — привязана |
| К4 | Мессенджеры (Telegram, VK, Instagram, WhatsApp, MAX): поля, разбор ссылки профиля, кнопка в шапке карточки и в клиенте, SMS без мессенджера, меню | К2 | малый–средний | кнопка открывает Telegram/VK/Instagram/WhatsApp, MAX — в браузере, без мессенджера — Сообщения |
| К5 | Стопка долгов: правило «долг», второй режим стопки по нажатию несданной съёмки | К4 для кнопки (без К4 — только звонок) | малый–средний | нажал несданную 20.10 — над ней все долги |
| К6 | Дни рождения, годовщина, «Поздравлять», уведомления 10:00, раздел мест со студийным часом | К2 | средний | поставить ДР на завтра — уведомление в 10:00 |
| К7 | Телефонная книга iPhone: «Из Контактов» (без разрешения); клиенты сами пишутся в книгу, тумблер (по умолчанию вкл), разовая запись уже собранных; чтение ДР и мессенджеров из книги | К2, К4 (мессенджеры в контакт) | средний–большой | новый клиент появился в Контактах iPhone; выключил тумблер — следующий не появился |

Порядок: К1 → К2 → К3 → К4 → К5 → К6 → К7. К5 можно взять раньше К3 (зависит только от стопки и
К4). Тяжёлое не параллельно (правило 26.09): по одному шагу.

### Решения Алексея (23.10) по шести вопросам

1. **Контакты iPhone** — «Пусть засоряют книгу, надо просто добавить кнопку вкл/выкл для этой
   функции, по умолчанию вкл». → клиенты сами пишутся в книгу, тумблер, по умолчанию вкл (§ 5).
2. **Строка «Контакты» в «Профиле»** — «оставить как есть, вернуться после месяца с «Клиентами»».
3. **Порядок стопки долгов** — самые старые долги ближе к открытой карточке. «Да».
4. **«Поздравлять»** включается само, как только вписана дата. «Да».
5. **Мессенджеры** — «Telegram, VK, Instagram, WhatsApp, MAX (его удалили из AppStore, но мы
   добавим, даже если не будет работать через приложение, можно туда поместить Web ссылку)».
6. **Клиент без номера** заводится, сам ни с кем не склеивается — только по подсказке. «Да».

Открытых продуктовых вопросов к К1–К7 нет; новые — при подходе к шагу.

## 9. Риски и что не проверить без телефона

- **Запись в Контакты:** не заведёт ли разовая запись уже собранных клиентов дубли (номера в книге
  записаны по-разному: «8…», «+7…», с добавочным), что делает iOS с контактами приложения при частичном
  доступе — только на телефоне. Контакты iCloud разъедутся на все устройства Алексея.
- **Разрешение Контактов** на бесплатной команде, вид системного окна, частичный доступ iOS 18+,
  поведение «Сохранить в Контакты» без разрешения — только на телефоне.
- **Мессенджеры:** открывает ли `t.me/+<номер>` чат, `vk.me` — приложение VK, а не браузер;
  есть ли у Алексея все три приложения — проверяется его пальцем.
- **Уведомления 10:00:** приходят ли от сборки бесплатной команды, у которой истёк 7-дневный
  срок подписи; переезд в другой пояс; делёж 64 мест при живой аренде и 40 поздравлениях —
  нужны тест расписания и одна неделя на телефоне.
- **Данные только на телефоне:** удаление приложения стирает клиентов (облака до 31). У каждого
  слота «LP …» — свои клиенты, сверять нельзя между слотами.
- **Веб выбрасывает раздел `clients`** при пересохранении — если файл-копию натива открыть в вебе.
- **Склейка ошибается:** общий семейный номер (мама записывает и себя, и дочь) склеит двух людей
  в одного клиента — разъединять придётся руками (кнопки «разъединить» в плане нет; добавить, если
  случится).
- **Слова** нового экрана — только натив (`Tools/lang_native.json`), нужны все пять языков веба.
- **Сколько краёв стопки помещается** при 15 долгах — из кода не видно, мерить в К5.
