Шаг 27а.1 (06.10.2026), только чтение кода, без запуска и замеров. Веб — `beta/index.html`
на `65eac94` (номера строк дрейфуют, якорь для `grep` — имя функции или класса). Натив —

## Коротко

1. **Бета тянет блок карточки прыжками, а не за пальцем.** Строка сидит на месте, пока палец
   не прошёл шаг 64 pt, потом перескакивает на новое место. Это записанное решение беты
   («плавное следование выглядело сломанным»). Режим «как маршрут на Карте» — это другое
   поведение: там строка идёт за пальцем, а на её месте стоит пустой слот.
2. **В нативе карточка повторяет бету один в один**: прыжки, без отдачи, без отмены жеста.
   Анимации есть только у входа и выхода из режима — и они не совпадают с бетой
   (кроссфейд 0,26 с против сворачивания блоков по высоте).
3. **Маршрут на Карте в нативе уже переписан с беты один в один** и хорошо работает как образец:
   удержание 250 мс, строка за пальцем, слот, автопрокрутка, отдача при подъёме, защита от
   прерванного жеста. Но соседи там расступаются мгновенно, а на отпускании строка
   прыгает на место без доводки — анимации «перестановки» в маршруте нет вовсе.
4. **Предлагаю** три шага: 27а.1б (бета, мелкий) → 27а.2 (сворачивание блоков в натив) →
   27а.3 (живой драг в натив). Весь драг блоков забираем из 29.3 в 27а.3.
5. Две развилки для Алексея — в конце документа.

## 1. Бета: вход, сворачивание, драг, выход

### Вход («ползунки» `#cardOrder` → `setOrderMode(true)` → `foldBlocks`)

| Что | Как | Строка |
|---|---|---|
| Высота плитки | блок меряется `offsetHeight`, ставится инлайном как точка отсчёта, **следующим кадром** (`requestAnimationFrame`) инлайн снимается, и блок едет к `height: 56px` | `foldBlocks`, ~28160 |
| Кривая и время сворачивания | `transition: height 0.26s cubic-bezier(0.25, 1, 0.4, 1)` | CSS `#cdEventBlocks.ord > *`, ~6159 |
| Начинка блока | `visibility: hidden` сразу, без перехода: плитка едет пустой, содержимое не видно с первого кадра | CSS ~6175 |
| Шапка строки (`.ord-cap`) | знак 32 + имя 15,5 + тумблер 40×24 + ручка 56×56; вставляется сразу, проявляется `ord-cap-in 0.22s ease` (opacity 0→1) | ~28150, CSS ~6167 |
| Вид плитки | сразу (без перехода): фон `--sheet`, радиус 14, без тени и рамки, поля 0; колонка `gap: 8px` | CSS ~6143–6150 |
| Что рядом | `cardEdit` (кнопка правки), `cardAdd`, `cdDelete` скрываются мгновенно, `cardOrder` получает класс `ok`, подвал `cdOrderFoot` появляется | `setOrderMode` ~28100 |
| Блоки, которых нет в этой съёмке | не сворачиваются, остаются `hidden`; выключенный (`dataset.off`) показывается приглушённым (opacity 0,4 у знака и имени) | `foldBlocks` |
| Reduced motion | `transition: none`, `ord-cap` без анимации | CSS ~6169 |

Что едет и что нет: едет только высота плиток (сжатие 56 pt, 260 мс); фон, радиус и
`gap: 8` меняются в первом кадре; содержимое гаснет в первом кадре; шапка проявляется за 220 мс.

### Драг (`dragBlock`)

- Жест: `pointerdown` на ручке (56×56, `touch-action: none`), **без удержания**, порог 4 px
  (`moved`), захват указателя `setPointerCapture` (в `try`). Тянуть можно только за ручку —
  иначе жест спорил с прокруткой листа.
- Шаг: `row.offsetHeight + rowGap` = 56 + 8 = **64**; место `want = clamp(startIndex +
  round(dy / 64))` по видимым блокам (`ordItems`).
- Что под пальцем: **ничего не едет**. Строка получает класс `drag` (фон `--press`, тень
  `0 8px 24px rgba(0,0,0,.45)`, `z-index: 5`) и **не двигается за пальцем**; `transform` не
  ставится. При смене места строка переставляется в DOM (`insertBefore`) — соседи и она сама
  встают на новые места мгновенно, без перехода.
- Комментарий в коде: «Строка не тянется за пальцем, а перескакивает по местам. Плавное
  следование выглядело сломанным: пока палец между двумя слотами, строка наезжала на соседа,
  а на её месте зияла дыра».
- Отдача и звук: **нет** (`tickClick` в `dragBlock` не вызывается).
- Автопрокрутка у краёв: **нет**. Блоков в нативе `CardBlock` — 15 (в вебе `CARD_BLOCKS` — 14),
  строка 64 pt, то есть до 960 pt в худшем случае при экране 852 pt: в полном наборе до
  края не дотянуться. Реальное число строк с данными — посчитать в 27а.3.
- Отпускание: `pointerup`/`pointercancel` → класс `drag` снимается, порядок пишется в
  `cardOrder[group]`, `saveAll()`. Доводки нет, строка уже стоит на месте.
- Отмена: `pointercancel` обработан (не залипает). Отдельной «отмены» вернуть прежний порядок нет —
  отпустил где стоит, там и осталась.

### Выход («Готово» / повторный тап по ползункам → `unfoldBlocks`)

- Целевую высоту не угадать, поэтому: `no-anim` на хосте → класс `ord` снимается → шапки
  скрываются (`display: none`, **без** затухания) → меряется `offsetHeight` каждого блока →
  каждому ставится `56px` и класс `ord-back` → один кадр → `height` = измеренная.
- Переход: те же 0,26 с и `cubic-bezier(0.25, 1, 0.4, 1)`, `overflow: hidden` у `ord-back`
  (начинка проступает по мере роста высоты).
- Через **280 мс** (`setTimeout`) высоты и `ord-back` снимаются, `cleanCaps` убирает шапки,
  вызывается `renderEventCard(s)` — карточка рисуется заново.
- `closeCard()` при открытом режиме сразу вызывает `setOrderMode(false)`.

### «По умолчанию» (`#cdOrderReset`)

Стираются `cardOrder[group]`, `cardOff[group]`, `s.questOff`; затем `unfoldBlocks(...)` →
в колбэке `applyOrder` + `applyOff` + `foldBlocks`. То есть **разворот на 280 мс, перестановка,
сворачивание снова** — на экране «мигание» карточки. Отдельной анимации перестановки при сбросе нет.

### Опросник

Строка опросника — не блок, остаётся на месте; в режиме вместо крестика у неё тумблер,
выключенный гаснет (`.ord-off`, opacity 0,4). Не сворачивается.

## 2. Образец — маршрут на Карте

### Бета (`rbHold`, `rbDragStart`, `rbDragMove`, `rbDragEnd`, ~16898–16985)

- Жест: удержание **250 мс** на номере (кружок 28×28), сдвиг > 8 px до срабатывания — отмена.
  `setPointerCapture`; `contextmenu` гасится.
- Подъём: пустой слот `.rb-slot` (фон `--hair-3`, радиус 6, высота строки) встаёт на место строки;
  строка уходит в конец разметки, становится `absolute`, класс `drag`: высота 34 (было 28,
  по 3 за края), радиус 10, фон `--peek-2`, тень `0 10px 24px --glass-cast`, кант
  `inset 0 0 0 1px rgba(226,164,76,.35)`, кружок номера 15→22 (`transition: width/height/
  line-height/font-size 0.12s ease`, ~3200). Отдача: `tickClick()` один раз при подъёме
  (звук + `navigator.vibrate(2)` там, где есть).
- Под пальцем: `translateY(dy)` строки без перехода — следует за пальцем кадр в кадр.
- Соседи: `insertBefore(слот, rest[to])` — **мгновенно** (переходов у `.rb-row` нет).
  `to = clamp(round((top + dy) / h))`. Номера соседей пересчитываются на каждой смене места
  (`rbRenumber`), поднятая строка показывает номер слота.
- Автопрокрутка: за 22 px от края окна `scrollTop ∓= 6` на каждое событие `pointermove`.
- Отпускание/отмена/уход пальца (`pointerup`, `pointercancel`, `pointerleave`) → `rbDragEnd`:
  класс снимается, слот удаляется, при смене места `mapRoute.splice`, `saveAll()`,
  `paintRouteNos(); placeRoutePath(); renderRouteBar(); routeReflow()`. **Доводки нет** —
  строка «падает» из-под пальца на слот в одном кадре. Линия маршрута на карте перекладывается
  только на отпускании («маршрутизатору незачем считать промежуточные порядки»).

## 3. Натив, как сейчас — карточка

`light_plan:native/.../Screens/Card/CardOrderList.swift` (138 строк), `CardBlocks.swift:20`,
`CardScreen.swift:108`, `App/AppModel+CardBlocks.swift:41–83`.

- **Вход/выход.** `CardScreen.tuneButton` — `withAnimation(.easeInOut(duration: 0.26)) {
  app.toggleCardTuning() }`. `CardBlocks.body` меняет `if app.cardTuning { CardOrderList } else {
  blocks }`: это **две разные ветки разметки**, а не сжатие тех же блоков. По умолчанию SwiftUI
  делает кроссфейд, высота листа интерполируется (в симуляторе не мерено). Сворачивания
  блоков по высоте нет, кривая другая (easeInOut вместо `cubic-bezier(.25,1,.4,1)`).
  Reduced motion не учтён.
- **Строка** `CardOrderList.row`: те же числа веба (56, зазор 8, знак 32, шрифт 15,5, тумблер
  ×0,784 → 49×22, ручка 56×56, `.opacity(off ? 0.4 : 1)`).
- **Драг** `CardOrderList.handle`: `DragGesture(minimumDistance: 4, coordinateSpace: .global)` на
  ручке, без удержания. Место `CardOrderDrag.slot(start:dy:count:)` = старт + `round(dy / 64)`.
  Поднятая строка (`hand == b`): фон `press`, тень чёрная 0,45 `radius 12, y 8`, `zIndex(1)` —
  **не двигается за пальцем** (`offset` не ставится), перестановка через `CardOrderDrag.preview` и
  `ForEach(shown, id: \.self)` без `.animation` — мгновенный прыжок. Как в бете.
- **Нет** отдачи (в `Card/` нет `sensoryFeedback`), нет автопрокрутки, нет слота-подложки.
- **Отмена жеста — дыра:** `hand` сбрасывается только в `onEnded`. Если систему прервёт жест
  (звонок, шторка, жест «назад»), `onEnded` не придёт, `hand` останется — строка залипнет в
  «поднятом» виде до выхода из режима. Тот же класс ошибки, что в замечании 5 ревью 24а; в
  маршруте исправлен `@GestureState holding`, в карточке — нет.
- **Спор с прокруткой листа** — не мерено. Ручка 56×56 внутри `ScrollView` листа: победитель
  между `DragGesture` ручки и скроллом решается порогом 4 pt и порядком; проверить на
  симуляторе в 27а.3 (как прокрутку проверяли в 24а).
- **Сброс** `resetCardOrder` — порядок и выключенные стираются, строки перестраиваются мгновенно,
  без анимации (в вебе — разворот/сворачивание). Результат тот же, путь короче.
- **Модель** `moveCardBlock(b, to: j, for: s)` пишет порядок группы жанров — менять не нужно:
  сколько бы ни ездила строка по экрану, в модель идёт один вызов на отпускании.

### Что значит «как маршрут на Карте» и как бета

Слово Алексея («живой драг, как перестановка точек маршрута») и бета **расходятся**: бета
намеренно не ведёт блок за пальцем. Если сделать только в нативе, натив уйдёт вперёд беты,
а правило проекта — бета эталон и аудит паритета (итерация 32) сверяет с ней. Поэтому предлагаю
сначала мелкий шаг в бете (**27а.1б**), потом натив.
