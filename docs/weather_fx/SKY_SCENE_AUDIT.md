## 1. Existing architecture (facts, from the repo)

- Single-file vanilla HTML/JS PWA, no build step. Working app: `beta/index.html`
  (~36.9k lines); root `index.html` is the stable copy. `sky.js` is only a constellation
  catalogue, not a renderer.
- No Swift, no Xcode project, no WidgetKit code in this repo. `SWIFT_MIGRATION_PLAN.md`
  (§ around line 74) states there is no WKWebView wrapper on disk; elsewhere (around line
  4286) it describes WidgetKit widgets built in a separate native repo, not reachable
  from this session.
- The live "Свет" screen sky is the dome: one inline SVG `viewBox 0 0 390 240`
  (`beta/index.html` ≈ 7711–7798): 280 star circles (`buildStars` ≈ 12224), meteors,
  horizon glow ellipse, day arc, sun (`paintSun` ≈ 14766, gradients `sunDeep/sunShade/
  sunGlow/sunCore`), moon (`paintMoon` ≈ 14686).
- Sky colour is already a function of sun elevation: `stateAt(t)` (≈ 12161, 15 states
  from astro night to noon) and `skyColor(e)` (≈ 12186, lerp ladder GOLD → SCARLET →
  PINK → BLUE → DEEP → NIGHT). Weather tints only the horizon glow below 8° sun elevation
  (`skyPalette(w)` ≈ 15079, `SKY_STOPS` ≈ 15072).
- **Weather is not drawn on the dome**: no clouds, rain, snow or fog layers. Weather
  appears as text and small icons (`skyIcon` ≈ 12113, `hwIcon/hwTemp/hwCond` ≈ 14931,
  `wxSign/wxSignHour` ≈ 29678).
- Daily weather state is coarse: `q ∈ {excellent, good, plain, fog, poor}` (`deriveQ`
  ≈ 11586); rain and snow both map to `poor`.
- Sky colours are JS constants; there are no CSS tokens for the sky. Theme: dark default,
  `:root[data-theme="light"]`.
- Design mockups (not wired into the app): `docs/claude_design_briefs/light_tiles_canvas/`
  (glass tiles incl. "Погода", generated by `build/gen_glass.py`).

### Weather data available (Open-Meteo, no key; `beta/index.html` ≈ 11679)

Hourly: `cloud_cover`, `cloud_cover_low/mid/high`, `relative_humidity_2m`,
`temperature_2m`, `wind_speed_10m`, `wind_direction_10m`, `wind_gusts_10m`,
`precipitation`, `weather_code`. Air quality: `aerosol_optical_depth`, `dust`.
Sun and moon positions are computed in-house (`computeSun` ≈ 10945, `elevAt`, `azAt`,
`moonAt` ≈ 11040).
**Not fetched:** `visibility`, `snowfall`, `rain` separately, `current=` block, dew point.

## 2. Target runtime

| Runtime | Exists? | Consequence |
|---|---|---|
| PWA in Safari / home-screen webclip (`beta/`) | yes, the working app | Canvas 2D, SVG, CSS, WebGL available; continuous animation possible while visible |
| WKWebView wrapper in Xcode | used for device tests, code not in repo | same WebKit engine as Safari; same rules |
| Native SwiftUI app | planned (`SWIFT_MIGRATION_PLAN.md`) | SwiftUI `Canvas` + `TimelineView`, Metal shader modifiers (iOS 17+) |
| WidgetKit widget | in a separate native repo, not reachable here | static SwiftUI snapshots from a timeline; no WebView, no DOM, no continuous animation |

So "the weather widget" in this repo means the dome and the weather tile/header of the
"Свет" screen in a PWA. A home-screen WidgetKit widget can only receive **static frames**
of the same scene model (see §6, stage D2).

## 4. Technology comparison (for the PWA; native column at the end)

Ratings are judgement unless a number is given. Measured numbers are from
`WEATHER_FX_GUIDE.md` §6 (headless Chromium, no GPU, not an iPhone).

| Criterion | CSS (and SwiftUI equivalents) | SVG (filters, masks) | Canvas 2D | WebGL / GLSL (Metal natively) |
|---|---|---|---|---|
| Visual quality | gradients, glow, shadows: good; no texture | soft cloud contours with turbulence: good static; lighting via `feDiffuseLighting` | particles, pre-rendered noise clouds with lit edges, lens drops: good (demo) | best: per-pixel scattering, volumetric clouds, true refraction |
| Performance | cheapest when only transform/opacity animate | animated `feTurbulence`/`feDisplacementMap` re-run per frame: expensive on large areas (not measured) | demo: 0.02–0.30 ms JS per tile draw; 8 tiles at 60/30 fps fine unthrottled; at 4× CPU 8 canvases together drop to ~9 fps (raster-bound) | per-pixel cost × area; README of atmosphere: 2160p ≈ 3.2× 1080p. Phone: not measured |
| Energy | low | medium–high if filters animate | low–medium; scales with fps and canvas count | highest; GPU busy every frame |
| Dev cost | low | medium (filter tuning by eye) | medium | high (shader, fallback, context loss) |
| Maintenance | low | medium (WebKit filter quirks) | medium | high |
| Platform fit (WebKit) | full | `feTurbulence` ok; `backdrop-filter: url()` likely not | full | WebGL 1/2 ok; context limit per page; context loss on background |
| Data-driven params | CSS variables | attributes / variables | any JS parameter | uniforms |
| Background / animation limits | stops with the page | stops with the page | rAF pauses when hidden | rAF pauses; context may be lost and must be rebuilt |
| Native analogue | SwiftUI gradients, `.blur`, `.shadow`, materials | SwiftUI `Path`, masks | SwiftUI `Canvas` + `TimelineView`, `CAEmitterLayer` | Metal; SwiftUI shader modifiers (iOS 17+) |

Minimal sufficient tool per effect (recommendation):

| Effect | Tool | Why |
|---|---|---|
| Sky gradient (dawn → day → sunset → dusk → night) | Canvas 2D gradient fed by existing `skyColor(e)` + elevation | already continuous in the app; needs more stops and an azimuth term, not a new engine |
| Sun disc, halo, scattering glow | Canvas 2D pre-rendered bloom sprite, `lighter` blend | demo: 3–4 draws per frame |
| Clouds with volume and light | Canvas 2D noise sprites with lit edge (demo method); WebGL only for one hero view | demo cost 0.02–0.08 ms per draw |
| Rain, snow | Canvas 2D particles, 3 depth layers | one stroke per layer |
| Fog / haze | Canvas 2D: horizontal noise bands + elevation-dependent white veil | cheap; no fetched visibility, see §5 |
| Drops on glass with distortion | Canvas 2D lens drops (inverted scene in a clip); optional WebGL normal-map refraction on one visible view | demo method; WebGL only if the device run allows |
| Water film, wet glass streaks | Canvas 2D: a few vertical blurred streak sprites + lowered contrast of the scene | needs prototype |
| Frosted card | CSS `-webkit-backdrop-filter: blur() saturate()` | already used by the glass tiles |
| Sun reflection on water | not needed for the dome (no water in the scene) | skip unless a water scene is added |

## 5. Scene model and data → render parameters

Two separate objects. Weather data never goes straight into drawing code.

**WeatherInput** (facts, per hour, from Open-Meteo + in-house astronomy):
`sunElev`, `sunAz`, `moonElev`, `moonPhase`, `cloudLow/Mid/High`, `cloudTotal`,
`precip` (mm/h), `code` (WMO), `humidity`, `aod`, `wind`, `windDir`, `temp`.

**SceneParams** (render, 0..1 unless stated), derived by one pure function:

| Param | Rule (heuristic, explicit) | Default if data missing |
|---|---|---|
| `skyTop`, `skyHorizon`, `glowColor` | from `sunElev` via `skyColor` ladder + weather tint (`skyPalette`) | clear sky at current elevation |
| `sunVisible` | `sunElev > −1°` × (1 − low/mid cover at sun azimuth, approximated by `max(cloudLow, cloudMid)/100`) | 1 |
| `sunGlow` | grows as `sunElev → 0` (longer air path), × `(1 + 0.5·aod)` | aod 0.15 |
| `lightDir` | from `sunAz` and `sunElev`; at night from moon | upper right |
| `cloudLayers[3]` coverage | `cloudLow/Mid/High / 100` | `cloudTotal` split 50/30/20 |
| `cloudDarkness` | `0.2 + 0.6·cloudLow·(precip > 0)` | 0.2 |
| `rain` intensity | `precip` mm/h: 0.1→0.15, 1→0.4, 4→0.8, ≥8→1; only WMO 51–67, 80–82, 95–99 | 0 |
| `snow` intensity | same scale, WMO 71–77, 85–86 | 0 |
| `thunder` | WMO 95–99 | 0 |
| `fog` | WMO 45/48 → 0.8; else `humidity ≥ 95 % and sunElev < 10°` → 0.3. Real visibility is not fetched; adding `visibility` to the Open-Meteo request is a one-word change, proposed for stage D | 0 |
| `glassDrops` density, size | follows `rain` (density 0.3 + 0.7·rain; size 0.6 + 0.4·rain); 0.15 for 2 h after rain stops | 0 |
| `glassWet` (film, streaks) | `rain > 0.6` | 0 |
| `glare` | `sunVisible · (1 − cloudTotal)` | — |

Transitions: SceneParams are interpolated over 1.5–3 s when the selected hour changes,
and the sky depends only on continuous `sunElev`, so dawn, day, sunset and night are one
ramp, not separate themes. Every layer has an on/off flag and is skipped when its
parameter is 0. `prefers-reduced-motion` → one still frame.

Scene coverage: clear day, partly cloudy, overcast, dawn, sunset, dusk, night, rain,
heavy rain, fog, snow and mixes (sun behind cloud; rain at sunset) are all points in
this parameter space, not separate code paths.

## 6. Recommended path and stage B plan

**Path.** Canvas 2D layer stack (from the measured demo) driven by SceneParams; CSS for
the frosted card; WebGL only as an optional higher-quality path for one visible hero
view after a device measurement. No new dependencies: `atmosphere` and `sunset-shader`
are MIT and used as algorithm references; any adapted piece gets the MIT notice.

**Stage B prototype: "Sunset after rain" scene.** One scene that exercises everything
asked: sunset gradient, low sun with soft glow, uneven clouds lit from below, wet glass
with water film streaks and lens drops refracting the sky.

Proposed files (to confirm before any edit):
1. `beta/sky_lab.html` — new lab page in the working app folder, next to the existing
   `beta/sandbox-glow.html`; does not change the app. Contains `sceneParams(input)`, the
   layer renderers, sliders for the inputs (sun elevation, cloud low/mid/high, precip,
   humidity, aod), a Canvas 2D vs WebGL toggle on the same input, the in-page measurement.
2. `docs/weather_fx/shots/sky_lab_*.png` — screenshots for review.
3. `docs/weather_fx/SKY_SCENE_AUDIT.md` — append stage C results.

Stage D (after review): integrate into the dome — a `<canvas>` behind the dome SVG
inside the `aboveHorizon` clip in `beta/index.html`, fed by `wxByHour[selDate][hour]`
and the existing `computeSun`; existing SVG sun/moon/arc stay. D2: for WidgetKit the
same SceneParams render static frames (SwiftUI) per timeline entry, in the native repo.
