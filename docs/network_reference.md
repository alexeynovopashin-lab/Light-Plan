## 3. Карта: что это на самом деле

**Холстов два** (`MapCanvasView.swift:84–95`): MapLibre (по умолчанию, iOS) и MapKit (на Mac
только он, и пункт «Apple» в настройках iOS).

**«Второй источник» = MapLibre + CARTO**, это не OpenStreetMap напрямую: стиль `Voyager`
лежит в приложении (`style_light.json`, `style_dark.json`, ~41 КБ), а *данные* —
векторные `.mvt` с четырёх поддоменов `tiles-{a,b,c,d}.basemaps.cartocdn.com` (Fastly), спрайт
и шрифты — с `tiles.basemaps.cartocdn.com`. Плитки идут с кэш-заголовком
`max-age=15552000` (180 дней, мерено), значит повторный просмотр уже виденной области сети
не просит, но только пока кэш MapLibre цел.

**Вызовы к Apple (из кода):**
1. Плитки холста «Apple»: SwiftUI `Map(...)` со стилем `.standard(elevation: .flat, emphasis: .muted, …)`
   (`MapKitCanvas.swift:25`). Что именно тянет система и с каких хостов — **не видно**.
   Единственный найденный в доке хост с `mapkit` в имени — `*.apple-mapkit.com:443`
   (Apple, «Use Apple products on enterprise networks»), и там он назван в разделе управления
   устройствами, **не** как источник плиток карты; остальные хосты карт на странице не названы
   — гадать не буду.
2. Маршруты: `MKDirections.calculate()`, по одному переходу подряд из-за предела частоты
   (`MKError.loadingThrottled`, комментарий `RoadRouter.swift:121`).
3. `CLGeocoder`: обратный геокодинг, поиск города, поиск места (3 файла).

**Почему «Apple грузится медленно»** — по коду ответить нельзя: ни таймаута, ни кэша,
ни выбора хоста в приложении для MapKit нет, всё делает система. Не мерено ни на телефоне Алексея,
ни из РФ; версия «частично доступные хосты Apple» — гипотеза, не вывод. Мера: прибор `diag.html`
пробует три адреса Apple (два из памяти, не подтверждены) и покажет время.

**Расхождение, которое надо знать.** `docs/17_NATIVE_ARCHITECTURE.md` § 9 пишет
«OSRM и Valhalla в нативе не едут: обе половины закрывает `MKDirections`», а код
(`RoadRouter.swift:49,57`) ходит в оба при холсте OpenStreetMap — решение Алексея 28.09
(DECISIONS) *«у MapLibre те же серверы, что у веба»*. Верно кодовое; строка в § 9 устарела
(в этом шаге не правил).

## 4. Маршруты — как сегодня

- Точки черновика → `RoadRouter.ask(source:mode:points:)`. MapLibre: машина — OSRM `GET` с
  `overview=full&geometries=geojson`, пешком — Valhalla `GET ?json=…`, формат ответа OSRM.
  MapKit: `MKDirections` по одному переходу.
- Таймаут не задан: `URLSession.shared.data(from:)` — системные 60 с (из доки, не мерено).
- `try? … ?? nil` — **любая ошибка = `nil`**, неотличимо от «нет дороги».
- Сбой кладётся в кэш сеанса как `.some(nil)` (`AppModel+MapRoute.swift:215`): кусок в этом сеансе
  **не перепрашивается**, остаётся прямой. После возврата связи линия не оживёт, пока не
  перезапустишь приложение или не сменишь холст.
- Без связи пользователь видит ту же прямую линию, что видел бы в режиме «дорога недоступна»;
  километры и минуты считаются по ней — **имитация**, нарушает «без имитации» (02.10).

## 5. Pinterest — как сегодня

- **Нативное приложение по ссылке Pinterest ничего не запрашивает** (grep: ни `URLSession`, ни
  `LinkPresentation`, ни `og:image` в нативе). Ссылка без картинки показывается плиткой «сайт
  (`RefLink.host`) + хвост пути» (`MoodboardFolder.swift:339`), открывается в мудборде листом
  кадра, а по тапу «открыть» — `openURL` во внешнем приложении/Safari.
- Картинка в кадре берётся из локальных файлов (`RefImageStore`); сетевой докачки превью нет.
- В вебе картинку по ссылке достаёт воркер Cloudflare `light-plan-og-reader`
  (`light-plan-og-reader.alexeynovopashin.workers.dev`, `beta/index.html:13526`) — читает `og:image`
  и целые доски через внутренний API Pinterest. Воркер веб-версии; нативу, по `docs/17` § 9, он
  «не нужен, телефон ходит напрямую» — но **этот запрос в нативе не написан**.
- Что из этого следует для 28л: «Pinterest-превью через наш сервер» — это не перенос, а **новая
  функция**: напрямую телефон из РФ до `pinterest.*` и `i.pinimg.com` может не достучаться
  (не мерено); через нашу функцию будет работать, только если *сам Yandex Cloud* достаёт Pinterest
  (не мерено; проверяется `curl` из функции, как в § 5 справки 28ж). Риск `og-reader`
  (недокументированный внутренний API Pinterest, бан по IP воркера) ложится на IP Yandex Cloud.
- Без связи сегодня: плитка-текст остаётся (она не из сети), «открыть» — ошибка внешнего приложения.

## 6. Детектор доступности — как делать

**Проба.** Для каждого сервиса — один дешёвый запрос тем же путём, каким ходит приложение
(погода уже пробует прямой 4 с → прокси; остальные — по аналогии):

| сервис | проба | успех |
|---|---|---|
| Погода | уже есть: `RoutedWeatherSource` | любой путь отдал разбираемый ответ |
| Плитки CARTO | `GET …/vectortiles/carto.streets/v1/14/<x>/<y>.mvt` (1,3 КБ, мерено) любой поддомен | 200 за 4 с |
| Карта Apple | нет честной пробы: хост неизвестен. Косвенно — первый `onMapCameraChange` после показа (из доки SwiftUI, не мерено) | см. открытый вопрос В1 |
| Маршруты | `GET` OSRM на два соседних пункта (3,5 КБ) | 200 + разобранная линия |
| Pinterest | `HEAD https://www.pinterest.com/` и `https://i.pinimg.com/` | ответ любым кодом за 4 с |
| Засветка | `HEAD` плитки ближайшего региона | 200 |
| Геокод | не проверяем отдельно: сбой `CLError.network` уже различим (`PlaceSheet.swift:250`) | — |
| Студия | уже честная ошибка по самому запросу | — |

**Режим «быстрая проба + запоминание».**
1. Таймаут пробы ≈ 4 с (как у погоды); «медленно» — ответ дольше 2–3 с (порог — предложение).
2. Результат `{сервис → ok / slow / down, время, момент}` держится в памяти, не на диске: связь меняется.
3. Срок: `ok` живёт ≈ 10 мин, `down` — ≈ 1–2 мин (чтобы вернувшуюся связь заметить быстро); для
   погоды остаётся принятое 3 ч для перепроверки прямого пути.
4. Повтор при смене сети: `NWPathMonitor` уже есть (`NetworkReachability`, подписан только
   `WeatherStore`) — подписать детектор: любое изменение пути = сбросить результаты и перепроверить
   то, что сейчас на экране.

## 8. Диагностическая страница

`Light_Plan/docs/network_diag/diag.html` — одна страница без внешних зависимостей, **v2 (28л.2, 03.10)**.
Открыть на Mac можно (`open docs/network_diag/diag.html`), но Mac не в сети Алексея — результат нужен
с телефона. В бакет Yandex (`lightplan`, ключ `diag/diag.html`) — **только по слову Алексея
«выкладывай»**, выкладку делает оркестратор; без этого слова файл в репозитории.

**v1 врала в этом** (результаты Алексея 03.10, `docs/network_diag/results_2026-10-03.md`): смотрела
`fetch(no-cors)` на **корень хоста**, поэтому «доступен» значило «хоть что-то ответило», а не «плитка,
маршрут, прогноз работают». Конкретно: `maps.apple.com` и `gspe1-ssl.ls.apple.com` — не годились как
проба даже с Mac; `disk.yandex.ru` дал ложное «нет» (на мобильном работает); `api.open-meteo.com` и
CARTO проверялись не тем путём, которым ходит приложение. v1 остаётся верна только для вывода «этот
хост достижим вообще» (контроль, Pinterest, `pin.it`).

**v2 бьёт в настоящие адреса из кода (`light_plan:native/`, main = `9f9b187`)**, статус даёт
по заголовкам и телу: «доступен» (ответ целиком < 3 с) · «медленно» (3–10 с) · «нет» (ошибка сети, нет
заголовков за 6 с, тело не дочитано за 10 с) · «дошли, но CORS» (cors-запрос упал, повторный
no-cors дошёл) · «ответ не тот» (HTTP не тот или JSON не разобрался). Для каждой строки время, размер и
скорость (байт/с; для тела < 4 КБ скорость не считается); тяжёлые строки идут по одной в конце.
Шапка: `navigator.connection` (в Safari нет — тогда пометка «укажи сеть сам») и время.

| Что | Как проверяет v2 (формат — как у приложения) | Что уточняет против v1 |
|---|---|---|
| плитка CARTO | `fetch` настоящей векторной плитки `.mvt` z12 Томск с `tiles-a`; стили светлый и тёмный берут **один и тот же** URL (разные только слои) | v1: корень `tiles-*`; плитка — **не картинка**, поэтому не `Image`; a–d сведены в одну строку |

| OSRM, Valhalla | `RoadRouter.webURL`: 2 точки, OSRM `overview=full&geometries=geojson`; Valhalla `/route?json=` pedestrian, `format=osrm`; тело разбирается как у приложения | v1: `/status` и без разбора |

| атлас засветки | `fetch` плитки `binary_tile_53_25` (Томск, 2025 = `Glow.year`), ~59 КБ | v1: заголовки, тело не качалось |
| Pinterest | публичная доска `…/pinterest/` на `www` и `ru` (no-cors: дошли ли) + `pin.it`; обложка `i.pinimg.com` через `Image`, скорость по известному размеру (17,6 КБ) | v1: корни хостов |

Проверка 03.10 с Mac (браузер превью, вне РФ, **не репрезентативно**): 18 проб из 18 дошли (два прогона: 18 «доступен»; во втором Open-Meteo «как у приложения» 3,0 с — «медленно»), JS-ошибок
нет; приём отказов проверен вручную: Pinterest-картинка через cors-fetch → «дошли, но CORS», несуществующий
хост → «нет». Не проверено: ветка «таймаут» (чёрная дыра браузер Mac отбивает мгновенно). На телефоне размер по
проводу (`encodedBodySize`) может не отдаваться — тогда показан размер после распаковки, скорость завышена;
в Safari `navigator.connection` нет.
Ограничение: `no-cors` строки (корни, Pinterest-страницы) не отличают 404 от 200 — важна достижимость; подмена
ответа по SNI для них неотличима.

## 9. Открытые вопросы к Алексею

Только продуктовые и денежные. Технические решения (формат пробы, сроки) — в § 6.

**В1. Что делать с пунктом «Apple» в настройках карты.** Apple-карту мы настроить не можем: хосты
системные, обойти через наш сервер нельзя.
- (а) Оставить как есть, пометить «может не грузиться вне белых списков». **Плюс:** 0 работы.
  **Минус:** в РФ часть людей выберет Apple и увидит серую карту.
- (б) Убрать «Apple» для устройств с регионом RU, оставить одну карту через наш сервер.
  **Плюс:** одна понятная карта. **Минус:** у тех, у кого Apple работает быстрее, пропадёт выбор.
- (в) Оставить, но автоматически переключать на нашу карту, если Apple не ответила за 4 с.
  **Плюс:** человек ничего не делает. **Минус:** сложнее, мерцание при переключении.
- **Мой выбор: (в) после того, как у нас будет своя карта; пока — (а).** Решение зависит от замера на телефоне.

**В2. Откуда брать карту, когда CARTO станет недоступна.**
- (а) Плитки через нашу функцию с кэшем в бакете. **Плюс:** быстро сделать; платим за вызовы. **Минус:**
  зависим от CARTO: их условия для коммерческого приложения не проверены (из памяти — бесплатно с
  указанием источника, **не подтверждено**).
- (б) Копия региона (Россия) в нашем бакете, один файл, без CARTO. **Плюс:** независимость, карта
  работает даже когда CARTO заблокирована. **Минус:** надо поднять квоту бакета и заранее скачать
  регион (размер неизвестен), обновлять раз в квартал.
- **Мой выбор: (а) сейчас, (б) — к выпуску.** Основание: (а) закрывает 28л за один шаг, (б) нужна
  всё равно к выпуску (план в `docs/17` § 10: «с подпиской — свой Protomaps»).
