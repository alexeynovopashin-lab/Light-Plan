## Главное до чтения

1. **Мудборд — это не «тег на референсе».** Плановая строка итерации 28 («не
   заводим новых сущностей: мудборд — это `tag` на референсе») **не совпадает с
   кодом**. В вебе три вещи: **кадр** (`shots[]`, L25858), **подборка** (`boards[]`,
   L25859: `kind` `shoot`|`tpl`, `items` — id кадров, `name`, `cover`, `sort`, `keep`)
   и **раздел-чип** на кадре (`shot.tags[]` — слова, они и есть «теги»; поля `.tag`
   давно нет). Подборка — уже сущность, и тип `RefBoard` в нативе (27) уже есть,
   только для чтения. Формулировку плана поправит оркестратор; в справке ниже
   «мудборд» = подборка (`board`), «тег/раздел» = слово на кадре.
2. **«Драга между папками» в вебе нет.** Кадр между папками переносят **листом**
   «Добавить в… / Переместить…» (L22191–22270), плитку подборки на плитку не кладут
   (жест слияния убран 31.08.2026, L23285). Перетаскивание — только
   **перестановка** плиток подборок в ряду (`mbStartDrag`, L21441) и кадров внутри
   одной папки (`mbGridDrag`, L21725). Отсюда «перенос без копий» — это
   **ссылка + снятие ссылки**, а не жест.
3. **Долгий тап мудборда — 420 мс** (`MB_HOLD`, L21382; в папке 420, L21823; обложка
   папки 420, L23202). Цифра «450» из инвентаря — от строки съёмки (`holdForFan`),
   к мудборду не относится (ошибка документа, не веба).
4. **Картинок в файле обмена нет.** Байты кадров — блобы в IndexedDB браузера
   (`im` — имя блоба), в `shots[]` лежат имя, размеры, путь в облаке, теги. Натив
   получает кадры без картинок (штриховка, решение 27 «1А»). Это главная
   развилка шага — см. «Развилки Алексею».

## 1. Сущности и откуда берётся содержимое

### Кадр (`shots[]`, L25858–25895)

`{ id, k: "img"|"link"|"doc", im?, path?, url?, w?, h?, tags?: [слова], pending?, mt }`.
`id` картинки = имя блоба `im` (`shotAdd`, L25884): «один файл — одно имя».
Ссылка без своей картинки — карточка-надпись (сайт + хвост пути, `refHost`/`refTail`).
Кадры лежат в **общем фонде**; владеет файлом фонд, а не подборка (L25835–25850).

### Подборка (`boards[]`)

| поле | смысл | строка |
|---|---|---|
| `id` | знак подборки | `newId()` |
| `kind: "shoot"` + `sid` | подборка **съёмки**; ищется по `s.id`, не по месту в списке; заводится лениво (`boardOfSession(s,true)`) | L25953 |
| `kind: "tpl"` + `genre` | папка **набора жанра** («заготовка»); у жанра их несколько — «полка» | L25973–25990 |
| `items[]` | порядок id кадров; один кадр — в многих подборках, **не дважды** в одной (`boardPut`) | L25903 |
| `name` | у основной папки жанра `null` (она и есть жанр), у остальных — своё имя | L25987 |
| `cover` | id кадра-обложки или `null` (автоматически — первый кадр с картинкой) | L22607 |
| `sort` | 0 вручную / 1 новые сверху / 2 по разделу | L22978, L23253 |
| `keep` | срок хранения на устройстве `{mode: day\|half\|ever\|shoot, at}` | L23160–23180 |
| `mt` | отметка правки для слияния устройств | — |

**Два рода папок.**
1. **Съёмочная** (`shoot`) — референсы одной съёмки; в «Съёмках» подписана
   «имя клиента / вид · дата · жанр»; жанр подборки = жанр съёмки (`syncBoardGenre`,
   L26000 — при смене жанра в форме).
2. **Набор жанра** (`tpl`) — многоразовая библиотека; на ленте один жанр — **одна
   плитка-полка**, сколько бы папок в нём ни было (решение Алексея 30.08.2026,
   `mbFolders`, L21149–21170). Папок одна — плитка ведёт сразу в кадры; больше
   одной — сначала список папок (`openFolderOrShelf`, L21976).
   **Основная папка жанра** — первая (`boardTpl`, L25976); на ней держится форма
   съёмки и «Добавить в подборку «жанр»».

**Первый запуск (`mbSeeded`, L26793–26800).** Каждому включённому жанру заводится
**пустая** папка `tpl` — по одной на жанр (в замере 12). Данные пишутся сразу.
Поэтому пустых жанровых подборок у нового человека 12; в счёте «N подборок» на
ручке ленты они считаются (`mbFolders` не отсеивает пустые жанры, L21160–21168).

**Откуда берётся содержимое карточки съёмки.** `allRefs(s)` (L29873): сначала
кадры **своей** подборки, потом кадры **всех** папок жанра `s.type` (`genreShots`,
L26030), кадр из двух мест — один раз, как свой. Это реализовано в нативе (27,
`RefSet.compose`).

### «Переложить» без копий

Все три действия — правка **ссылок**, файл один:

| действие | что делает | строки |
|---|---|---|
| «Добавить в…» (один кадр — из просмотрщика/поиска; пачка — из «Выбрать») | `boardPut(целевая, id)`; кадр остаётся и там, где был | L22228–22232 |
| «Переместить…» (пачка) | `boardPut(целевая)` + `boardTake(исходная)` + `boardPrune(исходная)`; **в ту же подборку — ничего не делает** (защита, L22234–22238) | L22233–22240 |
| «Добавить в подборку «жанр»» (в листе кадра **съёмки**) | `boardPut(boardTpl(жанр,true), id)`; у кадра съёмки папка остаётся | L23491–23502 |
| «Убрать из мудборда» | `boardTake`; кадр **исчезает насовсем** (`shotDrop`: фонд, блоб, облако, надгробие), только если больше нигде не лежит | L23504–23517, L25921 |
| «Удалить подборку» | `dropBoardWithShots`: подборка уходит, «одинокие» кадры (нигде больше не лежат) — насовсем; в подписи листа сказано сколько (`mb.delLone`) | L22141–22190, L26008 |
| «Объединить с…» (только папки жанра, через меню-шестерёнку) | кадры целевой + `boardDrop(from)`; окно «Вернуть» | L23291–23345 |

**Замер «без копий»** (Playwright, 30.09): выбрано 2 кадра из папки «Свадьба» (10
кадров) → «Переместить…» → «На море» (2 кадра, один из выбранных там уже лежал).
До: `shots` 19, «Свадьба» 10, «На море» 2. После: `shots` **19**, «Свадьба» **8**,
«На море» **3** (пришёл один: дубль не создан; id `zz_0`, `zz_3`, `sd_sh_wedding`).
Копий ни в фонде, ни в подборке нет.

Список «Добавить/Переместить» (`renderMbAddList`, L22208): сначала съёмки с
подборкой, потом папки жанров («Жанр · имя папки»), потом **жанры без подборки**
(тап заводит её на лету). В замере 17 строк: 4 съёмки + 11 папок жанров + 2
свободных жанра. В списке стоит и **текущая папка** (тап — no-op, при «Переместить»
защита не даёт стереть).

### Решения для натива (технические, приняты в шаге 1, обратимы; продублированы в DECISIONS)

- **Сущности не заводим новые, но типы дополняем:** `RefBoard` получает `id`, `name`,
  `cover`, `sort`, `keep`, `mt` (сейчас читает четыре поля из семи); `RefFrame` — `mt`.
  Неизвестные поля кадра и подборки при записи **не теряются** (сохраняем сырьём, как
  делает `Snapshot.extra`).
- **Перенос — операции над `items[]`** (`put`, `take`, `move`, `prune`, `dropWithShots`,
  `merge`), чистые функции в домене с теми же правилами, что в вебе: дубль в одной
  подборке запрещён, перенос в ту же подборку — no-op, кадр уходит совсем только
