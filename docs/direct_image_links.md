# Справка 28н.1 — прямые ссылки на фото в мудборде

Пометки: **мерено** — выполнено 05.10.2026 `curl` с этого Mac (выход в сеть через Германию, `ipinfo.io/country` = DE); **из кода** — прочитано, не запускалось; **не мерено** — знание или предположение.

## 1. Что отдают типичные источники (мерено)

| адрес (пример) | ответ | вывод |
|---|---|---|
| `images.unsplash.com/photo-…?w=800` | 200, `image/jpeg`, 84 КБ | **расширения в адресе нет**, картинка есть: по расширению не узнать |
| `www.gstatic.com/webp/gallery/1.webp` | 200, `image/webp`, 30 КБ | расширение и тип совпали |
| `upload.wikimedia.org/…/Example.jpg` | 200, `image/jpeg`, 9 КБ | то же |
| `picsum.photos/id/10/800/600.jpg` | 302 → CDN → картинка | **переходы обычны**: функции нужна проверка каждого |
| `i.imgur.com/removed.jpg` | 302 → `removed.png`, 200 `image/png` | **удалённая картинка отвечает 200 и заглушкой** (как `pin.it`, 28м § 8): тип и размер этого не ловят |
| `i.pinimg.com/…` несуществующая | 403 `application/xml` | 403 вместо 404 (у функции это уже 404) |

Что из этого следует для распознавания: по расширению (`.jpg .jpeg .png .webp .heic .heif`) узнаётся часть ссылок; крупные
сервисы (Unsplash и подобные) отдают картинку по адресу без расширения. Окончательно картинку определяет **заголовок
`Content-Type: image/*` и первые байты файла** (JPEG `FF D8 FF`, PNG `89 50 4E 47`, WebP `RIFF….WEBP`, HEIC `….ftypheic/heix/mif1…`).
Размеры: от единиц килобайт до нескольких мегабайт; оригиналы фото с сайтов фотографов бывают 5–20 МБ.

## 2. Открываются ли с мобильного в РФ напрямую

**Не мерено** (этот Mac выходит через Германию, из РФ не проверить). Известно из практики: часть зарубежных хостов картинок в РФ
не открывается без VPN (блокировки по хосту/CDN), часть открывается; отвечает ли конкретный хост, заранее не знаем и знать не можем —
хостов бесконечно много, белый список бессмыслен. Поэтому у приложения **два пути**: напрямую с телефона и через нашу функцию в
Yandex Cloud (она за пределами блокировок телефона, но не обязательно за пределами блокировок самого хоста).

## 3. Нужен ли путь через наш сервер и чем он рискует

Нужен как запасной: если телефон не достаёт хост, а Yandex Cloud достаёт. Риски открытого «скачай любой https-адрес»:

- **SSRF — главный.** Функция живёт в сети Yandex; у неё есть служебный адрес `169.254.169.254` (метаданные, отдаёт токен
  сервисного аккаунта), внутренние `10/8`, `172.16/12`, `192.168/16`, `127/8`, `localhost`, `*.internal`, IPv6 `::1`, `fc00::/7`, `fe80::/10`,
  `::ffff:a.b.c.d`. Недостаточно проверить строку адреса: имя `evil.example` может **резолвиться** во внутренний адрес, а адрес вида
  `https://2130706433/` — быть `127.0.0.1` (разбор URL это нормализует, имя — нет). Проверять надо **IP, на который реально идёт соединение**
  (на этапе DNS-запроса соединения), иначе подмена DNS между проверкой и соединением («DNS rebinding») обходит защиту.
- **Перенаправления:** внешний адрес отвечает `302 → https://169.254.169.254/`. Проверять после **каждого** перехода (≤ 3).
- **Огромные файлы:** читать потоком с потолком, не доверять `Content-Length` (его может не быть или врать).
- **Не картинка под видом картинки:** `Content-Type: image/jpeg` на HTML/скрипте. Проверять первые байты; SVG не принимать (в нём бывает скрипт);
  отдавать наружу заголовок типа **из байтов**, не из ответа хоста, плюс `X-Content-Type-Options: nosniff`.
- **Платформенный потолок ответа 3,5 МБ** (28м § 1.4: картинка идёт base64, +33 %): через функцию пройдёт файл **до 2,5 МБ**;
  больше — честное `413`, а не обрезка. Лимит 15 МБ возможен только на прямом пути телефона.
- **Злоупотребление как бесплатным прокси картинок:** ключ в `X-LP-Key` + лимит на IP + дневной потолок (у функции уже есть).

**Вывод.** Безопасно тянуть произвольный https-адрес можно, **только если** одновременно: https и порт 443; IP проверяется в момент
соединения (а не по строке); каждый переход ≤ 3 проверяется заново; чтение потоком с потолком 2,5 МБ; тип по заголовку **и** по байтам;
ключ и лимиты. Тогда белый список хостов не нужен. Остаточный риск: функция становится «картинным прокси» для держателя ключа
(ключ лежит в приложении) — ограничено лимитами; для публичного репозитория ключа в коде нет. Если проверка IP на уровне соединения
не пройдёт тестов, запасной вариант — только известные хосты (Unsplash, Wikimedia и т.п.), но он бьёт по цели «любой адрес».
