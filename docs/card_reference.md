## Фазы (`eventPhase`, L27856–27884)

```
at = shootAt(s)            // первая не-студийная точка с координатами, иначе первая, иначе placeLat/Lon
now = nowAt(at.lat, at.lon)   // «сейчас» по часам МЕСТА (пояс места − пояс телефона)
m = shootMin(s, now)       // минута шкалы съёмки: d·1440 + чч·60 + мм, d — день от s.date
if m == null: return dayDiff(now, s.date) < 0 ? before : after
to = s.end ?? s.min + (s.dur || 90)
if m < s.min           → before
if s.doneAt != null    → m < s.doneAt ? during : after
if manualEnd           → during
m <= to ? during : after          // конец включительно: минута конца ещё «во время»
```

- `shootMin` (L29065): `null`, если день «сейчас» раньше `s.date` или позже
  `floor(end/1440)` дней от него. Поэтому **ручное «во время» не держится за
  полночь последних суток съёмки**: на следующие сутки `m = null` → «после»,
  даже если «Завершить» не нажали.
- Границы по числам: портрет 18:47–19:47 — 18:46 «до», 18:47 и 19:47 «во
  время», 19:48 «после» (без ручного режима). Свадьба 19:10 → 03:10: `end =
  1630`, 00:31 второго дня — `m = 1471` «во время».
- Натив повторяет это целиком (`EventPhase.of`); `now` — `WallTime` места.
  **Замечено:** месяц «Съёмок» зовёт `EventPhase.of(…, manualEnd: false)` с
  днём и минутой телефона (`PlannerMonthView.swift:326`), веб в этом месте
  (L18963, `past3`) — `eventPhase` с настройкой и часами места. Шагу 2 —
  подать туда настоящий `manualEnd` и часы места.
- У каждой съёмки дня фаза своя (`12`, «День — контейнер»): утренняя может
  быть «после», пока вечерняя «до».

**Что меняет фаза в карточке** (всё — `renderEventCard` L28375 и ниже):

## «Завершать вручную» (`#manualEndToggle`)

- **Где:** «Настройки» → группа «Съёмки» (`set.grpShoots`) → последний раздел
  «Завершение съёмки» (`set.finish`, L8504): тумблер «Завершать вручную»
  (`set.manualEnd`) и заметка `set.manualEndNote` («Обычно съёмка
  завершается сама в записанное время конца. Включите, если снимаете дольше
  плана…»). По умолчанию выключено. В нативе раздел стоит тусклой строкой
  `foreign("set.finish")` (`SettingsChapterView.swift:148`) — шагу 2 сделать
  его настоящим.
- **Хранение:** снимок, верхний ключ `manualEnd` (L12387, чтение
  `!!saved.manualEnd` L13785). В нативе `AppSettings` его нет (лежит в
  `Snapshot.extra`).
- **Выключение снимает все отметки:** `sessions.forEach(delete s.doneAt)`
  (L33940) — иначе завершённая руками осталась бы завершённой без кнопки.
- **Кнопка:** «Завершить» (`day.finish`) в нижнем ряду `.card-acts`, слева
  от «Удалить», **не в плитке дня** (стояла там по DECISIONS 29.08, убрана
  1.09: «плитка дня — сводка, а не пульт»). Вид `.card-done`: обводка 1 px
  `--green`, без заливки, текст `--green`, padding 9×15, 14 px/600, радиус 999
  (L1795). Видна, только если `manualEnd && phase == during && сегодня
  (nowMinOf != null) && !notWork(s)`.
- **Нажатие** (L31516): `s.doneAt = чч·60 + мм` **по часам телефона**,
  сохранить, перерисовать карточку, список, календарь, день. «После»
  наступает тем же путём `eventPhase`, отдельной ветки «завершено» нет.
- **Строка «сверх плана»** (`day.overBy` «сверх плана {over} · по записи до
  {t}») достижима только в ручном режиме: съёмка без точек, «во время»,
  `endMin − now < 0`.
- **Ошибка эталона — пояс.** `doneAt` пишется часами телефона, а сравнивается
  с минутой по часам места. Телефон восточнее места (Томск +4 к Москве,
  съёмка в Москве): нажали в 19:00 по Москве → `doneAt = 1380` (23:00),
  `m = 1140` → «во время» ещё 4 часа. Западнее — «после» сразу (верно). На
  вторых сутках (`doneAt` < 1440, `m` ≥ 1440) выходит «после» — верно
  случайно. Натив (`Session.doneAt`: «минута суток по часам телефона»)
  повторяет веб. **Предложение шагу 2:** писать минуту шкалы съёмки по часам
  места (`s.minute(at: сейчас места)`); веб такое значение читает правильно
  (сравнивает с той же шкалой), поле то же.

## Студийный час (`paintStudio` L29198, `rentWindow` L28964; CSS L5880–5933)

**Окно аренды** `rentWindow(s)`: точки маршрута со студией из списка студий,
с `t` и `t2`, по `t`. Сегодня — та, что идёт (`t ≤ сейчас ≤ t2`), иначе
ближайшая впереди, иначе последняя; не сегодня — первая. Запись старого вида

**Когда видна:** есть окно, сегодня, `сейчас ≥ rw.from`, фаза не «после», и
до дедлайна > 0 с. Дошло до нуля — плитки нет («кончилась аренда — исчез
таймер», 8.09); после дедлайна не считает.

выходить на 5 мин раньше конца оплаченного. Секунды до него

суток: 93 300 − 1 800 = 91 500 с → таймер «25:25» вместо «1:25». Натив

### Свет — условие (инвариант 9; `lightCase` L27887–27948)

Три условия сразу:
1. **Пресет требует:** в пожеланиях записи есть `sunset`, `stars` или `moon`
   (`LIGHT_WISH`), и у места есть вечернее окно (`goldB` и `blueB` не пусты —
   не полярные сутки).
2. **Точка дня попадает в окно:** точки — маршрут (точки со временем и
   именем), без маршрута — часы съёмки (`shootHours`: от начала шагом 120 мин
   и сам конец; 18:47–19:47 → 18:47, 19:47). У каждой точки своё окно: солнце
   **места точки** (нет координат — якорь дня) и **её суток** (окно сдвинуто
   на `d·1440`). В окне: `goldB − 10 ≤ t ≤ blueB` (`GOLD_EARLY` = 10, только к
   началу золотого, Алексей 15.09). Первая такая — «попала»; иначе ближайшая
   по минимуму до `goldB` или `blueB`.
3. **Есть что сказать** — по порядку:
   - небо плохое (`poor` или `fog`) в сутки попавшей точки (или в день
     съёмки) → `.say.bad`: «Ожидался закат, а прогноз обещает {дождь} ·
     облачность {92}%.» (`light.waitedSunset`; слово — `qualCond.*` строчными);
   - попала → `.say`: ««{Прогулка}» попадает в золотой час: 18:40 – 20:05.
     Свет тёплый и мягкий.» (`light.inGolden`; без маршрута имя — «Съёмка»,
     `card.shootPoint`);
   - мимо не больше чем на 180 мин → `.say`: «Золотой час 18:40 – 20:05 —
     ближайшая точка «{Съёмка}» мимо на 1 ч 10 мин. Сдвиньте, если свет
     важен.» (`light.missGolden`, `durLabel`);
   - иначе — молчит.
- **Вид** `.say`: поля 11×14, радиус 14, `--sheet-3`, 13,5 px, шаг 1,45,
  `--ink-3`, gap 9; знак 16 (`sun`, `--brass`, 1,5; у `.bad` — `warn`,
  `--terra`); у `.bad` — терракотовый свет по периметру (`--glow 201,102,61`,
  как у студийного часа; у натива есть `WarnGlow`). Обычный свет — без
  свечения.
- **Свет у точек** (`routeLight` L27775, `pointLight` L27802): состояние
  света в минуту каждой точки (её место, её сутки; вечернее в пределах
  `goldB − 10` считается золотым). Говорит только тон `excellent`: золотой →
  знак `golden`; рассвет, светает → `sunrise`; закат, сумерки, синий час →
  `sunset`, у синего — цвет `--blue`; слово — имя состояния. Где: слово в
  строке маршрута (27), знак 16 под колонкой погоды (ниже), точка «Золотой»
  на ленте плитки дня (правило — раздел «Плитка дня»).
- **Натив:** `LightCase.of(_:route:spots:studios:evening:skyIsBad:)` и
  `LightCase.hours` есть, сверены (`OverlapsAndLightParityTests`); нет
  `routeLight`/`pointLight`, точки «Золотой» на ленте, вида строки. `evening` —
  из `SolarDay` места и суток; `skyIsBad` — **из прогноза точки**, не места
  приложения (ошибка 6), и не из выдумки (развилка 1).

### Погода

**Прогноз по точкам** (`ptFetch` L11710–11820): у карточки свой кэш.
- Ключ — широта и долгота с 3 знаками (~100 м) + дата; три этапа в одном
  месте — один вопрос сети.
- Окно — от −5 до +15 дней от сегодня телефона (`ptReach`); дальше сервис
  отвечает ошибкой 400, веб не спрашивает.
- Какие точки: якорь дня (`shootAt`: первая не-студийная точка с
  координатами, иначе первая, иначе место записи) + первые 6 точек маршрута
  (`cardWxPts` L28347); повторы схлопнуты ключом.
- Один запрос на все точки (Open-Meteo принимает список координат),
  `hourly` = облачность (всего, нижняя, средняя, верхняя), влажность,
  температура, ветер, направление, порывы, осадки, `weather_code`;
  `timezone=auto`; даты — от дня съёмки до последних суток съёмки (через
  полночь). Сутки точки собирает та же сборка, что общий прогноз (у натива —
  `WeatherDay.buildDays(from:place:air:)`), с солнцем **этой точки**.
- Пока летит — ключ «в пути» (прочерки); пришёл пустой — запоминается пустым
  (не спрашивать по кругу); сеть оборвалась — ключ освобождается, спросит
  следующее открытие. Воздух (дым в закатный балл) — только якорю, окно ±5 дней.
- Пришёл ответ — карточка перерисовывается целиком, если она всё ещё открыта
  на той же записи. После съёмки не спрашивается.

### Решения для натива (приняты на шаге 1, обратимы)

- **Закрепление `AFTER_FIRST` убрано (шаг 6, слово Алексея):** все плитки двигаются в любой фазе. Бета в фазе «после» ставит плитку дня под сделку, документы, гонорар и сдачу даже при сохранённом порядке «первой» (замер 29.09, y 666 против 301–588).

- Пустые значения в сохранённом порядке пропускать при чтении (1).
- Перестановка не трогает места блоков, которых в этой съёмке нет (2).
- В перестановке — только блоки; студийный час и тревоги в список не
  складываются (3); перерисовка не ломает режим (4).
- Открытая свёртка остаётся открытой, пока карточка открыта (5).
- Свет и `#cdWarn` судят о небе по прогнозу точки съёмки (6). Запись без
  места прогноза не ждёт: панели часов нет, плитка места без погоды — «место
  неизвестно, светить нечему», как в форме (DECISIONS 16.09); точка маршрута
  без координат берёт погоду якоря, как у веба (8). «Дальше» работает и на
  вторые сутки (9); город под местом — только `placeTown` (10).
- Цвета — токенами темы (11); сделка — на `--sheet-3`, как все плитки (12).
- `#cdWarn` молчит при «Неважно» и когда прогноз совпал с пожеланием: туман
  ↔ туман, осадки ↔ дождь (13).
- Строка документа — знак и имя во всю оставшуюся ширину (15).
- Тревога прогноза читает `notif` и `wxSeen` из снимка веба (по умолчанию

### Развилки — Алексею (шаг 1, 29.09)

1. **Погода в карточке дальше 16 дней**, где прогноза нет (ошибка 7).

   В) часы и знаки света остаются, вместо погоды — прочерки.
   Выбор исполнителя — Б: инвариант 11 «прибор не врёт»; запись DECISIONS
   16.09 «без сети выдумка лучше прочерка» — про форму без сети, не про
   горизонт.
