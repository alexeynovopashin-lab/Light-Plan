## Главное

1. **Живого сервера ядра нет вообще.** Event OS — это документы (00–99, BRIDGE_*, 15_Core_Modules, 16_Place_Registry) плюс заготовка `app/` из четырёх HTML-страниц и `core/*.js`, которые читают демо-проект из `localStorage` браузера. В `app/` нет ни одного `fetch`, сервера, воркера, базы. Договор «общий API /v1/, ИИ, дашборд» сам пишет: «Ничего не построено и не развёрнуто». Всё, что Light Plan «получает от ядра», сегодня — это файл-копия, лежащая в `workspace/20_shared`.
2. **Реально работающие сетевые каналы у Light Plan идут не в ядро, а в серверы BroniOS (Cloudflare Worker `tomson-auth`) и в Яндекс-функции** (погода, читалка Pinterest). `broni-auth` тоже отвечает (200), но приложение на него не переключено.
3. Из всего списка того, что должно ходить между Light Plan и ядром, **в нативе есть три вещи**: запрос «есть ли у студии моя бронь» (в BroniOS, не в ядро), общий список студий (файлом в сборке), правило «свет в окнах» (в виде функции + файла сверки). Остальное — на бумаге.
