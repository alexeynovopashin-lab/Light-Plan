# Читалка og:image и досок Pinterest

По присланной ссылке (Pinterest, Instagram, что угодно) читает метатег
`og:image` и отдаёт байты картинки; для доски Pinterest умеет забрать список
всех пинов целиком, через внутренний resource-API самого сайта (не
официальный OAuth v5 — тот чужую публичную доску перечислить не даёт).
Ничего не хранит, логов не пишет. Разбор — в `docs/15_MOODBOARD.md`, разделы
«Про посредника — и почему он временный» и «Доски».

## Развернуть

Через мастер настройки Cloudflare (Workers → Create → вставить `worker.js`)
— или из терминала:

```bash
cd og-reader
npx wrangler login
npx wrangler deploy
```

Разворачивается как есть: без переменных окружения, без привязок KV/D1,
без секретов. После деплоя Cloudflare даст адрес вида
`https://light-plan-og-reader.<твой-подадрес>.workers.dev`.

## Проверить

```bash
curl "https://<адрес-воркера>/?url=https%3A%2F%2Fwww.pinterest.com%2Fpin%2F<id>%2F" -o test.jpg
curl "https://<адрес-воркера>/?board=<ссылка-на-доску,encodeURIComponent>"
```

Первая — должен прийти файл картинки. Ссылка без og:image (или
несуществующая страница) — ответ 404, это ожидаемо: клиент в этом случае
просто оставит текстовую карточку, как было до читалки.

Вторая — JSON `{ name, pinCount, pins: [{ id, permalink, image }] }`; сами
байты картинки пина — отдельным вызовом `?img=<image, encodeURIComponent>`.
Доска не нашлась или лазейка перестала отвечать — 404, клиент откатится на
одну обложку через `?url=`.

## Обновить

```bash
cd og-reader
npx wrangler deploy
```

Разворачивается на аккаунт, под которым выполнен `wrangler login` — это
может быть не тот аккаунт, что дал воркер через мастер настройки Cloudflare
в первый раз (разные подадреса `*.workers.dev`). После деплоя сверьте адрес
в выводе команды с `OG_READER_URL` в `beta/index.html` — если подадрес
другой, константу нужно поправить вручную.

## Дальше

Адрес воркера нужно подставить в `beta/index.html` (константа
`OG_READER_URL`) — без этого читалка развёрнута, но ничем не вызывается.
